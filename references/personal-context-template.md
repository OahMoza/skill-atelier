# 个人化上下文

> 决定 Skill Atelier 产出的技能"长成你的样子"。动手设计/制造前读本文件，并按 `profile.yml` 或 `~/.skill-atelier/profile.yml` 应用。

## 1. 为什么需要个人化

同一个能力，不同人的技能写法完全不同：语言、术语、格式偏好、风险容忍度、目录习惯、质量标准。不个人化的技能 = 通用模板 = 智能体每次都要重新猜你怎么想。

## 2. profile.yml 字段说明

| 字段 | 含义 | 影响 |
|---|---|---|
| `language` | 生成技能正文的语言 | 模板与内容的默认语言 |
| `output_style` | concise / detailed 等 | 步骤颗粒度、示例数量 |
| `risk_tolerance` | 风险容忍度 | 哪些操作写进"必须确认" |
| `require_confirmation_for` | 需确认的高风险操作列表 | 技能内的执行守则（删文件、git push、云部署、数据库写…） |
| `preferred_tools` | 文档/表格/演示偏好的产出格式 | 技能输出契约的默认格式 |
| `directories.skills` | 技能安装目录 | build 阶段的落盘位置 |
| `directories.drafts` | 草稿目录 | 设计文档、评估报告、审计报告的落盘位置 |
| `defaults.template_language` | 模板语言 | 生成技能的语言 |
| `defaults.include_validation_checklist` | 是否带定稿清单 | SKILL.md 是否含验证章节 |
| `defaults.version_on_create` | 创建即带版本号 | 是否默认声明扩展字段 version |

## 3. 个性化注入点

设计/制造每个技能时，至少在这些点代入个人配置：

1. **触发描述**：用你的术语和触发场景写（"用户说什么话会触发它"）；
2. **输出契约**：默认格式按 `preferred_tools`（文档→docx/pdf，表格→xlsx，演示→pptx）；
3. **风险守则**：把 `require_confirmation_for` 写进技能的失败行为/执行守则；
4. **目录约定**：输入输出路径遵循你的项目布局习惯；
5. **质量标准**：什么算"完成"（你过去的纠正、验收口径）。

## 4. 个人上下文模板（无 profile 时的兜底提问）

没有 profile 或信息不足时，按顺序问（一次别问太多）：

- 这个技能平时会怎么被用？举 1–2 个例子；
- 产出格式有偏好吗（文档/表格/演示/纯文本）？
- 有没有绝对不能碰的操作（删除、推送、付费调用…）？
- 用中文还是英文？术语习惯？
- 装到哪个目录？

## 5. 维护与隐私边界

- **不推断敏感信息**：不从工作记录猜测你不愿共享的个人信息；
- **不访问授权路径之外的文件**：只读你明确给出或 profile 声明的目录；
- profile 是活文档：你的偏好变了就改它（语言、目录、风险清单），生成器会自动跟随；
- 不要把一次性任务指令写进 profile（"这次用这个文件"不算稳定偏好）。
