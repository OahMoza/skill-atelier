# 反模式清单

> 每个反模式给出：症状 → 后果 → 对策。审计（/atelier audit）时逐条对照。

## 1. 空想制造（Vague Generation）
- **症状**：不读任务记录/项目文件，直接让模型"写个技能"，产出全是"处理错误"、"遵循最佳实践"式空话。
- **后果**：技能没有你的真实上下文，智能体用起来等于没有。
- **对策**：先做一次真实任务再提取；或用真实 runbook/schema/评审意见综合。见 `skill-design-principles.md` §1。

## 2. 描述过宽 / 过窄
- **症状**：该触发不触发（过窄）；不该触发乱触发（过宽）。
- **后果**：技能库越来越吵，触发率下降，用户开始手动纠正。
- **对策**：走 trigger-optimization 的 20 条查询评估 + 训练/验证切分。见 `trigger-optimization.md`。

## 3. 重复制造（Re-invention）
- **症状**：每遇到相似需求就新建技能，`detect_duplicates.py` 相似度居高不下。
- **后果**：触发互相抢、维护成本翻倍、指令冲突。
- **对策**：新建前强制查重；重叠就走合并 + 退役。见 `lifecycle-management.md` §4–5。

## 4. 为存在而存在的资源（Decoration Assets）
- **症状**：references/ scripts/ assets/ 目录建了但没人读、没人跑。
- **后果**：浪费磁盘和上下文预算，技能变重。
- **对策**：原则 6——用不到就不建；校验时确认每个资源都被 SKILL.md 引用。

## 5. 跳过验证（Skip Validation）
- **症状**：写完就宣布完成，脚本没跑过、引用路径是错的、目录名和 name 不一致。
- **后果**：技能装上去才报错，返工成本翻倍。
- **对策**：`validate_skill.py` 无 Error 才算完成，脚本必须实际运行。

## 6. 一稿定终身（Ship-and-Forget）
- **症状**：技能创建后再没更新过；你的纠正没有回流。
- **后果**：技能与真实工作方式脱节，慢慢变成没人用的死技能。
- **对策**：把每次纠正写进 Gotchas；用使用日志驱动维护。见 `lifecycle-management.md` §2–3。

## 7. 不维护不退役（Hoarding）
- **症状**：技能库只增不减；低价值技能占着触发空间。
- **后果**：触发噪声上升，好技能被淹没。
- **对策**：定期 /atelier audit；长期不用即退役候选。

## 8. 过度工程（Over-engineering）
- **症状**：一开始就做跨平台转换、评测排行榜、自动安装、多 Agent 协作。
- **后果**：核心闭环（发现→制造→校验→迭代）没跑通就背了一堆壳。
- **对策**：先聚焦个人候选发现 + 规范制造 + 结构校验 + 使用反馈迭代；闭环稳定后再加。

## 9. 把纠正当噪音（Correction Amnesia）
- **症状**：用户纠正了三次，技能文档一个字没改。
- **后果**：每次都重蹈覆辙，用户失去信任。
- **对策**：纠正 = 最直接的迭代输入，立即进 Gotchas + bump patch。

## 10. 目录/命名漂移（Naming Drift）
- **症状**：name 与目录不一致、大写、连续连字符、一个技能塞多个职责。
- **后果**：加载器找不到技能，触发路由失效。
- **对策**：scaffold 时校验 + validate 时复核。见 `agentskills-spec.md` §2.2。
