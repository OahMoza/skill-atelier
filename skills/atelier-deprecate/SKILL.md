# atelier-deprecate · 退役

技能库只增不减 = 触发噪声上升。本技能负责**安全瘦身**：判定 → 迁移 → 处置 → 记录。

## 何时使用

- `/atelier deprecate <skill 路径>`；
- `/atelier audit` 发现低价值/重叠项；
- 技能长期不用或被完全替代。

## 判定标准（满足其一）

1. **长期不用**：超过 staleness 阈值（默认 90 天）且无恢复迹象——用 `../../scripts/analyze_skill_usage.py` 确认，不凭印象；
2. **被完全替代**：新技能覆盖其全部能力（查重报告佐证）；
3. **不再匹配工作流**：对应任务已不存在或已改流程。

## 流程

1. **确认判定**：跑 analyze_skill_usage.py（有日志时）+ detect_duplicates.py，收集证据。
2. **标记 deprecated**：在描述开头声明"已废弃（deprecated），被 <替代技能> 替代"，避免继续被触发选中。
3. **迁移依赖**：找出引用该技能名的流程/文档/其他技能，更新为替代方案。
4. **处置**：
   - 有重叠 → 合并进保留技能（把 Gotchas 和边界情况并入，再退役）；
   - 无重叠 → 归档：移入 `drafts/archived/` 保留证据（推荐，可逆）；
   - 删除文件是高风险操作：按 profile.yml 的 `require_confirmation_for` 确认后再删。
5. **记录**：输出处置报告到 drafts/，写明判定依据、迁移动作、处置方式。

## 处置报告模板

```
# <skill> 退役报告
判定依据：长期不用（xx 天，日志/无日志）/ 被替代（<技能>）/ 流程变更
证据：…
迁移动作：…（引用了它的地方已改）
处置：归档到 drafts/archived/ / 合并进 <技能> / 已删除
日期：
```

## 非目标

- 不凭"感觉没用"就删——要有判定证据；
- 不删有活跃使用或可恢复的技能；
- 不确定时选归档而不是删除（可逆 > 不可逆）。

## Gotchas

- 退役先迁移后标记，别先删后通知——引用它的流程会静默坏掉；
- 合并时被并入方的 Gotchas 必须带过去，否则知识丢失；
- 归档目录用日期前缀（archived/2026-09-29-skill-name/），保留可审计历史。
