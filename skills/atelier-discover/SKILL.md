# atelier-discover · 发现

判断"这个反复出现的事，值不值得做成 Skill"，输出候选评估报告。只做判断和报告，**不生成任何文件**。

## 何时使用

- `/atelier discover`；
- 用户说"这个流程我每次都这么干，能不能做成技能"；
- 你观察到同一类请求/操作反复出现。

## 输入

- 用户请求或任务描述；
- 可用的工作记录/聊天记录/项目文件；
- 使用日志（若有，`../../scripts/analyze_skill_usage.py` 的输出可作证据）。

## 评估清单（逐项过，全部要有证据）

1. **重复性**：出现过几次？≥2–3 次才算候选；一次性的不算。
2. **确定性**：是否有固定步骤、固定输入输出、固定格式？
3. **通用模型差距**：不做成技能，智能体能否稳定干好？能 → 暂不创建。
4. **触发清晰度**：能否写清"做什么 + 何时用"？写不清 → 暂不创建。
5. **替代方案**：是否已被既有技能覆盖？查 `../../scripts/detect_duplicates.py`。
6. **资源可行性**：需要哪些 scripts / references / assets？来源有没有？

## 输出（候选评估报告，落到 drafts/）

```
候选名称：
候选类型：快捷操作 / 流程 / 知识包 / 治理系统
触发场景：
非目标：
当前替代方案：
证据：（具体记录/文件/日志条目，不凭印象）
建议：新建 / 并入（<目标技能>）/ 暂不创建
```

## 建议判定

- **新建**：重复 + 确定 + 通用模型干不好 + 触发可写清；
- **并入**：与既有技能重叠 ≥ 阈值（查重报告）或能力是某技能的子集；
- **暂不创建**：一次性、太模糊、模型本来就能干好、或暂无资源来源。

## 非目标

- 不设计技能（那是 atelier-design）；
- 不创建目录/文件（那是 atelier-build）；
- 不做触发优化（那是 atelier-validate）。

## Gotchas

- 别把"我想要个技能"当证据；要有真实任务/记录佐证；
- 别拿通用模型会做的事情当候选——技能的价值在于模型**缺的上下文**。
